# v1.0.2 release notes — BTT Eddy temperature migration

## Scope

v1.0.2 adds a guarded migration for existing **K1 Max + official CFS + BTT Eddy Duo** installations on the already-validated **CrealityOS 2.3.5.33** profile.

The supported hardware/firmware target is unchanged:

- Creality K1 Max
- official Creality CFS upgrade
- CrealityOS 2.3.5.33
- BTT Eddy Duo over USB
- fixed CFS napkin-strip wipe
- Fluidd + Moonraker/Nginx

This release does **not** expand support to other CrealityOS versions, different mainboards, CFS-C conversions, or other Eddy wiring/topologies.

## What changed

### Existing-install Eddy temperature migration

Added:

```sh
sh install.sh upgrade-temperatures
```

The command upgrades an older working Eddy installation that already has:

- `[mcu eddy]`
- `[probe_eddy_current btt_eddy]`

but lacks one or both graphable temperature objects.

It adds only the missing objects:

```ini
[temperature_sensor btt_eddy_mcu]
sensor_type: temperature_mcu
sensor_mcu: eddy
min_temp: 0
max_temp: 105

[temperature_probe btt_eddy]
sensor_type: Generic 3950
sensor_pin: eddy:gpio26
horizontal_move_z: 2.0
```

Fresh installs generated by the current helper already contain these objects; the new command is primarily a migration path for existing calibrated installs.

### Non-destructive behavior

The migration is intentionally narrow:

- requires the expected Eddy MCU/probe layout before writing;
- refuses to overwrite conflicting existing temperature sections;
- creates a timestamped rollback backup only when a change is required;
- does **not** rewrite the existing `[probe_eddy_current btt_eddy]` section;
- preserves drive current, height/frequency calibration, offsets, native-Z routing, homing logic, CFS macros, and wipe configuration;
- does not issue a restart, motion, probing, heating, wipe, or print command;
- is idempotent: a second successful run reports that the upgrade is already present and makes no changes.

### Status reporting

`sh install.sh status` now reports both temperature-object states:

```text
Eddy probe temp:       present
Eddy MCU temp:         present
```

or `missing/invalid` when the expected configuration is absent or does not match the validated USB Eddy layout.

## Live reference-printer validation

The migration was validated on the K1 Max + official CFS + BTT Eddy Duo reference printer running CrealityOS 2.3.5.33.

Before migration:

- Eddy drive current: `16`
- height/frequency map: `101` points
- native Eddy Z: active
- production safety profile: pass
- fixed napkin wipe: configured
- START_PRINT CFS order: pass

After migration and `FIRMWARE_RESTART`:

- Klipper returned `ready`;
- `temperature_probe btt_eddy` reported a live probe temperature of approximately `39.33 C`;
- `temperature_sensor btt_eddy_mcu` reported a live MCU temperature of approximately `43.9 C`;
- drive current remained `16`;
- the 101-point height/frequency calibration remained present;
- native Eddy Z remained active;
- the production safety profile still passed;
- the fixed napkin wipe and CFS startup ordering remained valid.

A repeated migration run returned:

```text
Eddy temperature upgrade already present; no files changed.
```

The final production verification reported:

```text
7 EXACT, 2 EXPECTED CUSTOM, 0 DRIFT
Result: production safety profile accepted
```

The Eddy config is expected to classify as `EXPECTED CUSTOM` after this migration because the added temperature sections change the file bytes while the calibrated/safety structure remains valid.

## Temperature monitoring versus compensation

This release exposes the Eddy probe thermistor and Eddy MCU temperature to Klipper/Fluidd.

It does **not** automatically create or enable a thermal-drift compensation calibration. On the validated printer, the live `temperature_probe btt_eddy` object loaded normally with compensation disabled.

Do not assume that adding the graph sensor is equivalent to completing a temperature-drift calibration.

## Existing installation upgrade

From an updated checkout:

```sh
sh install.sh status
sh install.sh upgrade-temperatures
```

Review `/usr/data/printer_data/config/btteddy_mcu.cfg`, then issue in Fluidd:

```text
FIRMWARE_RESTART
```

After Klipper returns ready:

```sh
sh install.sh status
sh install.sh verify-production
```

No Eddy drive-current or height-map recalibration is required merely to add these temperature objects because the calibrated probe section is preserved.

## Compatibility

**Validated target remains CrealityOS 2.3.5.33 only.**

Do not treat v1.0.2 as validation for 2.3.5.34, 2.3.5.35, the newer 1.1.x K1 Max firmware line, a different mainboard, a CFS-C conversion, or an Eddy Coil configuration.
